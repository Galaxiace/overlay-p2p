# Захват защищённого RPC для проверки этапа 4

## Что понадобится

- Wireshark с установленным Npcap и поддержкой захвата loopback-трафика.
- Проект с настроенным `.venv`; новые Python-пакеты для захвата не нужны.
- Два окна PowerShell или два терминала PyCharm.

## Запись захвата

1. В Wireshark выберите интерфейс `Adapter for loopback traffic capture` (название может немного отличаться) и начните захват. Если такого интерфейса нет, установите Npcap с включённой поддержкой loopback.
2. В первом терминале запустите защищённый узел:

   ```powershell
   .\run.bat peer_demo.py node --port 9400 --state-dir .state\pcap-node
   ```

3. Во втором терминале отправьте PING с уникальной контрольной строкой:

   ```powershell
   .\run.bat peer_demo.py ping --host 127.0.0.1 --port 9400 --message "TLS_SECRET_CHECK_20261017" --state-dir .state\pcap-client
   ```

   В ответе должно появиться `PONG: TLS_SECRET_CHECK_20261017`, а в терминале узла — запись о принятом PING.

4. Остановите захват в Wireshark. В поле display filter введите `tcp.port == 9400`; в списке должны отображаться пакеты подключения и зашифрованные TLS-записи.
5. Через **File → Save As** сохраните полный захват, например как `results\stage4-control.pcapng`. Если каталога `results` нет, создайте его командой:

   ```powershell
   New-Item -ItemType Directory -Force results
   ```

6. В Wireshark откройте **Edit → Find Packet**, выберите поиск строки в байтах пакета и выполните поиск `TLS_SECRET_CHECK_20261017`. Контрольная строка не должна находиться в сетевых пакетах. В деталях пакетов должно быть видно, что прикладной обмен идёт в TLS.

После проверки остановите узел сочетанием `Ctrl+C`. Если `run.bat` спросит о завершении пакетного файла, ответьте `Y`. Не прикладывайте `.state`: там находятся закрытые ключи и локальный тестовый CA.
